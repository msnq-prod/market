# Вкладка: Дашборд

## Сейчас

Файл: `src/admin/pages/Dashboard.tsx`.

Дашборд загружает `/api/admin/dashboard-summary`, показывает версию и несколько KPI-карточек со ссылками на товары, пользователей, приемку и склад.

## Проблемы UX/UI

- Это набор ссылок, а не рабочий стартовый экран.
- Нет приоритетов: просрочки, ошибки, блокеры, заказы и партии не собраны в одну очередь.
- Версия проекта занимает отдельный блок, хотя это системная информация.

## Новая реализация

`HQ Overview`: командный экран с приоритетами дня.

- верхняя строка KPI только по действиям;
- блок `Требует внимания`;
- очереди партий, заказов, media и системных ошибок;
- короткие CTA к конкретным подпунктам mega-nav.

## Вторая строка mega-nav

- `Сводка`: KPI и быстрые действия.
- `Операции`: партии, склад, продажи.
- `Риски`: просрочки, stuck-состояния, ошибки.
- `Релиз`: версия desktop/API, обновления.

## Реализовано

Файл: `src/admin/pages/Dashboard.tsx`.

- `Сводка`: KPI, очередь внимания и быстрые переходы.
- `Операции`: отдельные рабочие панели поставки, Планеты и продаж/склада.
- `Риски`: отдельная очередь блокеров и контрольные плитки.
- `Релиз`: версия проекта и pre-release checklist.
- `Состояние`: health checklist по доступным frontend/API сигналам.
- Прямые маршруты: `/admin/operations`, `/admin/risks`, `/admin/release`, `/admin/system/status`.
- Legacy URL `?view=operations`, `?view=risks`, `?view=release`, `?view=status` сохранены как compatibility fallback.

Файл: `src/admin/components/AdminLayout.tsx`.

- заголовок страницы теперь меняется для прямых overview routes и legacy query routes.
