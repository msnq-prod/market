# A01 — что еще нужно проверить

## Перед проектированием

1. Подтвердить у владельца продукта, нужен ли отдельный ежедневный `Обзор`, или стартовой страницей должна стать очередь задач по роли.
2. Уточнить, кто реально использует `Релиз`; при отсутствии пользователя убрать его из основной IA.
3. Определить реальные SLA/правила stuck-состояний для партий, заказов, возвратов и медиа.
4. Зафиксировать приоритет 5–7 действий, которые ADMIN выполняет ежедневно на компьютере.
5. Решить, должны ли `Товары` и `Планета` быть разными зонами: сейчас карточка товара одновременно участвует в поставке, публикации и цифровом паспорте.
6. Проверить термины с конечными пользователями: `Планета`, `Паспорта`, `Распределение`, `Медиа-центр`.

## Перед реализацией

1. Согласовать единый route registry как источник истины для ACL, навигации, title и layout type.
2. Проверить 1920×1080 и минимальную поддерживаемую desktop-ширину.
3. Проверить все роли (`ADMIN`, `MANAGER`, `SALES_MANAGER`) отдельными screenshot-наборами.
4. Получить контракт настоящей очереди исключений; не выводить синтетические «риски» до появления источника.
5. Решить судьбу скрытых `/brandbook` и `/prototypes/*`: удалить из production bundle, закрыть dev-флагом или перенести в Storybook.

## Гипотезы, не считать подтвержденными

- Стартовая страница по роли может быть полезнее общего Dashboard.
- Глобальное меню, открывающее компактную карту workflow, может заменить постоянный второй ряд.
- `Релиз` и версия, вероятно, относятся к системному меню, а не к ежедневным операциям.
- Часть `Планеты` может быть объединена в единый редактор публикации, но это требует проверки зависимостей Product/Location/Item.
