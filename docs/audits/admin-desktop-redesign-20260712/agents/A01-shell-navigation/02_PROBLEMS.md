# A01 — подтвержденные проблемы

## P0

В этой зоне P0 не подтверждены. Критические ACL/auth-находки зафиксированы в A04.

## P1

### A01-001 — «Состояние системы» показывает ложноположительные проверки

- **Доказательство:** `Сессия администратора` и `Центр статуса` имеют `ok: true` без запроса или runtime-проверки (`src/admin/pages/Dashboard.tsx:517-527`).
- **Влияние:** оператор получает зеленое подтверждение отсутствующей проверки.
- **Скриншот:** `05-system-status.jpg`.
- **Решение:** показывать только реальные probes с временем проверки; неизвестное состояние обозначать `Нет данных`, а не зеленым.

### A01-002 — обещание «API и очереди» не соответствует источнику данных

- **Доказательство:** единственный запрос — `/api/admin/dashboard-summary`; endpoint возвращает только десять счетчиков (`server/index.ts:510-558`).
- **Влияние:** экран не видит застрявшие заказы, media jobs, Telegram, desktop runtime и фоновые очереди.
- **Решение:** либо сузить экран до честной `Сводки данных`, либо создать отдельный агрегированный health/queue contract.

### A01-003 — риски построены из общих счетчиков и могут неверно трактовать нормальные состояния

- **Доказательство:** любая партия `TRANSIT`, любой HQ-остаток выше online и любая неопубликованная карточка превращаются в «риск» (`src/admin/pages/Dashboard.tsx:825-896`). Нет срока, SLA, причины, владельца или конкретного объекта.
- **Влияние:** постоянный шум; пользователь перестает доверять блоку внимания.
- **Решение:** очередь исключений должна состоять из конкретных объектов с бизнес-правилом, возрастом, владельцем и доступным действием.

## P2

### A01-004 — четыре уровня дублируют одну навигацию

- **Доказательство:** верхняя зона, второй ряд подпунктов, левая навигация Dashboard и карточки быстрых переходов ведут в одни и те же места.
- **Скриншоты:** `01-dashboard.jpg`–`05-system-status.jpg`.
- **Влияние:** интерфейс требует читать больше, но путь не становится короче.
- **Решение:** оставить один постоянный глобальный уровень; локальные режимы показывать только там, где они являются этапами одной задачи.

### A01-005 — подписи навигации занимают высоту и объясняют очевидное

- **Доказательство:** каждый подпункт содержит название и описание (`HqMegaNav.tsx:171-177`).
- **Влияние:** две строки меню съедают рабочую высоту и ухудшают сканирование.
- **Решение:** краткие однозначные названия; пояснение только в tooltip для редких/неочевидных функций.

### A01-006 — активная зона определяется fallback-ом, а не принадлежностью маршрута

- **Доказательство:** неизвестный маршрут получает `groups[0]` (`HqMegaNav.tsx:70-74`).
- **Скриншот:** `06-brandbook.jpg`, где скрытая системная страница визуально относится к `Обзор`.
- **Влияние:** ложное чувство местоположения.
- **Решение:** все рабочие маршруты должны иметь явную принадлежность либо полноэкранный режим без глобальной подсветки.

### A01-007 — разный shell для wide и non-wide маршрутов не связан с задачей

- **Доказательство:** whitelist вручную перечисляет почти все URL, остальным добавляет отдельную шапку и `Status Center` (`AdminLayout.tsx:336-383`).
- **Влияние:** скрытые маршруты получают случайную лишнюю шапку; визуальная иерархия зависит от списка URL.
- **Решение:** layout задается типом workspace (`list-detail`, `editor`, `fullscreen`, `settings`), а не исключениями pathname.

### A01-008 — обзор использует одну трехколоночную оболочку для пяти разных задач

- **Доказательство:** все route exports возвращают один `DashboardWorkspace`, а правый `DashboardInspector` рендерится всегда (`Dashboard.tsx:102-120`, `212-281`).
- **Скриншоты:** `01-dashboard.jpg`–`05-system-status.jpg`.
- **Влияние:** большие пустые области, нерелевантный инспектор, повтор рисков и быстрых ссылок.
- **Решение:** сводка — компактный command center; системная диагностика — таблица probes; релиз — убрать из ежедневной админки или сделать реальным deployment view.

### A01-009 — «Операции» не позволяет выполнять операции

- **Доказательство:** экран состоит из трех `WorkflowPanel` со счетчиками и ссылками (`Dashboard.tsx:327-375`).
- **Скриншот:** `02-operations.jpg`.
- **Влияние:** лишняя промежуточная страница.
- **Решение:** либо удалить, либо превратить в единую очередь конкретных задач дня с прямыми действиями.

### A01-010 — «Релиз» не является рабочей функцией продукта

- **Доказательство:** одна env-версия и четыре ссылки (`Dashboard.tsx:454-498`).
- **Скриншот:** `04-release.jpg`.
- **Влияние:** техническая служебная информация занимает пункт основной навигации.
- **Решение:** версия — в меню профиля/системной диагностике; релизный экран нужен только при наличии реальных checks, истории и права обновления.

### A01-011 — риск выводится одновременно в центре и инспекторе

- **Доказательство:** `RisksDashboard` показывает `risks`, затем общий `DashboardInspector` снова выводит `AttentionQueue` (`Dashboard.tsx:379-450`, `618-652`).
- **Скриншот:** `03-risks.jpg`.
- **Влияние:** прямое дублирование и потеря полезной ширины.
- **Решение:** один список исключений; боковая панель только для выбранного объекта.

### A01-012 — прототипы не проверяют специализированные задачи

- **Доказательство:** все варианты используют общий контракт `metrics/actions/links/Preview` (`prototypes/shared/types.ts:32-44`) и статические данные.
- **Скриншоты:** `07`–`12`.
- **Влияние:** визуальная вариативность скрывает отсутствие информационной архитектуры.
- **Решение:** прототипировать конкретные критические сценарии: принять Item, обработать новый заказ, распределить Item, исправить media blocker, опубликовать карточку.

## P3

### A01-013 — чрезмерная карточность и большие радиусы снижают информационную плотность

- **Доказательство:** почти каждый текстовый блок обернут в отдельную панель с `18–24px` radius.
- **Влияние:** интерфейс выглядит как презентация, а не рабочий инструмент.
- **Решение:** таблицы/строки для списков, разделители вместо вложенных карточек, радиус 6–10px только там, где нужен контейнер.

### A01-014 — низкий контраст вторичного текста делает инструкции трудночитаемыми

- **Доказательство:** большая часть пояснений использует `text-gray-500/600` на почти черном фоне; скриншоты `01`–`12`.
- **Влияние:** пользователь вынужден вчитываться в текст, который интерфейс сам добавил как помощь.
- **Решение:** удалить необязательные пояснения; оставшийся текст довести до стабильного контраста.

### A01-015 — смешение русского и английского языка

- **Доказательство:** `HQ Admin`, `Admin UI reference`, `Status Center`, `runtime`, `Item`, `Hero`, `Media` встречаются в рабочих экранах.
- **Влияние:** интерфейс выглядит незавершенным и менее понятен неподготовленному оператору.
- **Решение:** русский язык по умолчанию; технические термины оставлять только когда это точное имя сущности/инструмента.
