# A01 — shell, навигация, обзор и прототипы

## Контекст

- Проверено на desktop `1440×900` в локальном E2E-окружении.
- Роль наблюдения: `ADMIN`.
- Основания: маршруты, React-компоненты, ACL, API сводки и свежие скриншоты `01`–`12`.
- Эта зона не меняет бизнес-данные: она должна помогать выбрать задачу, увидеть исключения и перейти в профильный workspace.

## 1. Глобальная оболочка

### Что делает сейчас

1. Проверяет наличие `accessToken`, роль и перенаправляет между admin/partner/public.
2. Ограничивает продажи для `SALES_MANAGER`, скрывает продажи от `MANAGER`, оставляет системные настройки только `ADMIN`.
3. Показывает два постоянных уровня навигации:
   - верхний: `Обзор / Продажи / Товары / Планета / Система`;
   - нижний: все страницы выбранной зоны с названием и пояснением.
4. Для большинства новых workspace растягивает контент на всю ширину; для исключений добавляет отдельную шапку с названием, описанием и `Status Center`.
5. Сохраняет поддержку старых query-маршрутов `?view=` и `?queue=` параллельно с новыми URL.

### Зачем это нужно

- Обеспечить единый вход в админку и ролевую маршрутизацию.
- Дать оператору стабильную карту задач.
- Не позволить роли увидеть чужие рабочие зоны.

### Фактическая структура

| Уровень | Количество | Назначение |
|---|---:|---|
| Основные зоны | 5 | Группировка по домену |
| Подпункты `Обзор` | 4 | Сводка, операции, риски, релиз |
| Подпункты `Продажи` | 9 | Этапы заказа + CRM/остатки/история |
| Подпункты `Товары` | 7 | Партии, приемка, медиа, QR, склад, распределение |
| Подпункты `Планета` | 6 | Локации, карточки, публикация, подписи, паспорта, QR |
| Подпункты `Система` | 5 | Статус, пользователи, медиа, Telegram, настройки |

Источники: `src/admin/components/navigation/adminNavigation.ts:53`, `src/admin/components/navigation/HqMegaNav.tsx:64`, `src/admin/components/AdminLayout.tsx:289`.

## 2. Обзор HQ

Все пять URL используют один `DashboardWorkspace` и один запрос `GET /api/admin/dashboard-summary`.

| URL | Заявленная задача | Реальная функция |
|---|---|---|
| `/admin` | Ежедневная сводка | 4 суммарных счетчика и переходы |
| `/admin/operations` | Текущие операции | 3 универсальные карточки процессов со ссылками |
| `/admin/risks` | Просрочки и stuck-состояния | Эвристики из 9 суммарных счетчиков |
| `/admin/release` | Релиз и обновления | Строка версии и 4 ссылки |
| `/admin/system/status` | API и очереди | Доступность только summary API плюс два статических зеленых статуса |

API считает только локации, карточки, пользователей, партии в двух статусах и Item в двух складских статусах. Дедлайнов, заказов, возвратов, очередей медиа, Telegram, desktop runtime и фоновых задач в ответе нет.

Источники: `src/admin/pages/Dashboard.tsx:102`, `src/admin/pages/Dashboard.tsx:129`, `src/admin/pages/Dashboard.tsx:327`, `src/admin/pages/Dashboard.tsx:501`, `src/admin/pages/Dashboard.tsx:825`, `server/index.ts:510`.

### Постоянная компоновка

- слева — еще одна навигация по тем же пяти режимам;
- в центре — контент текущего режима;
- справа — одинаковый инспектор: риски, быстрые действия, версия и счетчики.

Из-за этого одна и та же информация одновременно присутствует в верхней навигации, левой панели, центральном экране и правом инспекторе.

## 3. Скрытые/референсные страницы

### `/admin/brandbook`

Назначение — визуальный справочник компонентов. В рабочей навигации отсутствует. На экране смешаны русская админка, английское название `Admin UI reference` и системный `Status Center`. Маршрут не распознается навигацией и подсвечивает первую группу `Обзор`.

### Прототипы

| URL | Идея | Фактическое состояние |
|---|---|---|
| `/admin/prototypes/mega-menu` | Большое меню задач | Наиболее понятная workflow-группировка, но статическая и чрезмерно крупная |
| `/admin/prototypes/sidebar-v2` | Вертикальная навигация | Еще одна оболочка вокруг тех же данных |
| `/admin/prototypes/workspaces` | Каталог рабочих областей | Те же метрики/actions/preview в карточках |
| `/admin/prototypes/command-matrix` | Матрица команд | Те же данные, переупакованные в таблицу действий |
| `/admin/prototypes/focus-deck` | Фокус на одной зоне | Те же данные, переупакованные в deck |

Все прототипы основаны на одном типе `AdminPrototypeFeature`: `metrics`, `actions`, `links`, `Preview`. Данные захардкожены по четырем темам (`physical`, `sales`, `planet`, `system`) и не отражают реальные очереди. Это четыре оформления одного универсального блока, а не четыре проверенных модели решения задач.

Источник: `src/admin/prototypes/shared/types.ts:4`.

## 4. Что в текущей философии стоит сохранить

1. Деление на понятные бизнес-зоны.
2. Постоянное верхнее позиционирование в системе.
3. Разделение очереди и детальной работы.
4. Визуальное выделение главного действия.
5. Полноэкранные специализированные инструменты для QR, фото, видео и 3D.
6. Идею `mega-menu`: показывать не перечень сущностей, а последовательность рабочих задач.

## 5. Вывод по зоне

Новая оболочка выглядит цельно, но архитектурно подменяет задачи универсальным трехколоночным шаблоном. Навигация объясняет интерфейс текстом вместо того, чтобы сокращать путь. Обзор не является командным экраном: он показывает общие числа без владельца, срока и следующего действия. Прототипы подтверждают исходную причину — сначала создан универсальный контейнер, затем в него вставлены разные домены.
