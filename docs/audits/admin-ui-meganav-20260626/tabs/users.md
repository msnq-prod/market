# Вкладка: Пользователи

## Что есть сейчас

Route: `/admin/users`.

`Users.tsx` показывает список аккаунтов и базовые операции с доступами:

- верхний title-band `Аккаунты и доступы`;
- кнопки `Обновить`, `Добавить`;
- метрики: всего, админы, продажи, партнеры, Telegram;
- поиск по имени, email, Telegram username/chat_id;
- фильтр ролей: все, админы, менеджеры, продажи, партнеры;
- таблица пользователей: имя, email, короткий id, роль, баланс, Telegram, статус;
- модалка создания пользователя;
- модалка ручной привязки Telegram chat_id/username;
- статус пользователя всегда отображается как `Активен`;
- для Telegram есть подсказка про `/start` и перенос `chat_id` из вкладки Telegram.

## UX/UI проблемы

- Страница работает как широкая таблица с модалками, а не как системный ACL-инструмент.
- Нет выбранного пользователя и постоянного inspector с последствиями роли.
- Роли показаны бейджами, но не объясняют зоны доступа.
- Нет сценария изменения роли существующего пользователя.
- `Статус` всегда `Активен`, без реального управления блокировкой/деактивацией.
- Telegram-привязка редактируется в модалке и оторвана от общего профиля пользователя.
- Добавление пользователя уходит в modal-only сценарий; контекст ролей и ограничений не виден.
- Метрики занимают верхнюю площадь и не помогают основной операции.
- Нет явного разделения обычных действий и опасных действий.
- На узких экранах таблица требует горизонтального скролла и плохо поддерживает быстрое сравнение.

## Как должно выглядеть

Three-zone модель для раздела `Система`.

- **Left rail:** поиск, фильтры ролей, фильтры статуса/Telegram, компактный список пользователей.
- **Center workbench:** таблица или master-list пользователей с ролью, email, балансом, Telegram-состоянием, последней активностью.
- **Right inspector:** выбранный пользователь, роль, зоны доступа, Telegram, audit/status, опасные действия.

Центр должен быть рабочей зоной сравнения. Inspector должен быть местом принятия решений.

## Ожидаемое состояние

- Пользователь выбирается из списка без открытия модалки.
- В inspector видны имя, email, id, роль, баланс, Telegram chat_id/username, дата `/start`.
- Роль редактируется в inspector с пояснением последствий.
- Telegram-привязка редактируется в inspector, рядом с подсказкой откуда взять chat_id.
- Создание пользователя открывается как inspector/drawer, не перекрывая список.
- Статус аккаунта должен отражать реальные данные. Если backend не поддерживает деактивацию, статус не показывать как управляемый.
- Опасные действия отделить в `Danger zone`.
- Метрики сократить до компактной системной сводки в правой зоне или убрать из первого экрана.

## Нужные правки

- Перевести `/admin/users` на layout `left rail + center workbench + right inspector`.
- Добавить состояние `selectedUserId`.
- Перенести поиск и фильтры в left rail.
- Перенести карточку выбранного пользователя, Telegram-форму и role explanation в inspector.
- Заменить modal-only создание пользователя на drawer/inspector-сценарий.
- Добавить явные empty/loading/error состояния для списка и inspector.
- Проверить ACL: создание `ADMIN` и редактирование Telegram доступны только разрешенным ролям.
- Не показывать несуществующие действия деактивации, пока нет backend-контракта.

## Быстрые действия

- Создать пользователя.
- Обновить список.
- Скопировать email.
- Скопировать user id.
- Привязать или очистить Telegram.
- Показать зоны доступа выбранной роли.
