# Вкладка: Обзор

## Что есть сейчас

Файл: `src/admin/pages/Dashboard.tsx`.

Маршруты:
- `/admin` — сводка дня.
- `/admin/operations` — операционный контур.
- `/admin/risks` — риски и блокеры.
- `/admin/release` — релиз и обновления.
- `/admin/system/status` — состояние системы.

Все маршруты используют один `DashboardWorkspace`.

Источник данных один: `GET /api/admin/dashboard-summary`.

Доступные KPI:
- товары всего / опубликовано;
- локации всего / с опубликованными товарами;
- пользователи / франчайзи;
- партии `TRANSIT` / `RECEIVED`;
- items `STOCK_HQ` / `STOCK_ONLINE`.

### `/admin`

Сейчас:
- общий header с kicker, заголовком, описанием;
- два KPI-pill: активная работа, риски;
- 4 крупные карточки: товары и локации, пользователи, партии в пути, товары на складе HQ;
- блок `Требует внимания`;
- блок быстрых переходов.

Переходы ведут в товары, пользователей, партии, склад, приемку, распределение, публикацию.

### `/admin/operations`

Сейчас:
- 3 панели workflow:
  - поставка и приемка;
  - планета и публикация;
  - продажи и склад.
- внутри каждой панели: 3 метрики и набор быстрых ссылок.

Экран ближе к карте процессов, но без реальной очереди задач.

### `/admin/risks`

Сейчас:
- список рисков формируется только из summary KPI и ошибки загрузки;
- блокеры:
  - summary API не загружен;
  - есть партии `RECEIVED`;
  - есть партии `TRANSIT`;
  - есть неопубликованные карточки;
  - есть локации без опубликованных товаров;
  - HQ-остаток выше онлайн-остатка.
- справа 3 контрольные плитки: приемка, публикация, склад HQ.

Риски не имеют приоритета, SLA, владельца, возраста и состояния обработки.

### `/admin/release`

Сейчас:
- показывает `VITE_PROJECT_VERSION` или `dev`;
- отдельная панель контрольных переходов:
  - состояние системы;
  - media readiness;
  - desktop tools;
  - операции.

Это технический блок, визуально оформлен как полноценный экран.

### `/admin/system/status`

Сейчас:
- локальный health checklist:
  - dashboard summary API;
  - auth session;
  - desktop status center;
  - data snapshot.
- справа быстрые переходы: пользователи, desktop, приемка.

Проверки частично декларативные: auth session и desktop status center отмечаются как ok без реального backend health probe.

## UX/UI проблемы

- Обзор перегружен крупными декоративными панелями и KPI-карточками.
- Одинаковый большой header повторяется на всех режимах и занимает рабочую высоту.
- `/admin` конкурирует с рабочими страницами вместо того, чтобы вести в конкретные очереди.
- KPI не всегда отвечают на вопрос "что делать сейчас".
- `/admin/operations` показывает карту процессов, но не показывает текущие рабочие элементы.
- `/admin/risks` называется рисками, но работает как набор эвристик по KPI.
- Нет сортировки рисков по срочности, возрасту, владельцу или влиянию.
- `/admin/release` и `/admin/system/status` слишком тяжелые для сервисных экранов.
- `Состояние системы` пересекается с системной зоной админки и desktop status center.
- Нет единой правой панели с контекстом выбранной зоны.
- Нет явного разделения: навигация слева, рабочая область в центре, инспектор справа.
- Cards имеют большой радиус и маркетинговую подачу; для HQ-инструмента нужен плотный операционный UI.
- Состояния loading/error есть, но они не превращаются в actionable recovery flow.

## Как должно выглядеть

Целевая концепция: `left rail + center workbench + right inspector`.

### Left rail

Назначение:
- верхнеуровневая навигация по зонам;
- быстрый переход между обзором, физическим контуром, планетой/публикацией, продажами, системой;
- активное состояние маршрута без дублирования вкладок внутри рабочей области.

Для обзора:
- пункт `Обзор`;
- вложенные подпункты только если они реально нужны:
  - `Сводка`;
  - `Операции`;
  - `Риски`;
  - `Релиз`;
  - `Состояние`.

### Center workbench

Назначение:
- основная очередь внимания;
- компактные таблицы/rows вместо hero и крупных карточек;
- рабочие действия рядом с объектом.

Для `/admin`:
- первый экран — attention queue;
- строки: тип, счетчик, причина, целевой маршрут, действие;
- KPI только как компактные chips над очередью или в строках.

Для `/admin/operations`:
- process map заменить на операционную доску;
- группы:
  - приемка;
  - media readiness;
  - публикация;
  - склад/распределение;
  - продажи.
- каждая группа: счетчик, состояние, ближайшее действие, переход.

Для `/admin/risks`:
- таблица блокеров;
- поля: приоритет, зона, сигнал, количество, возраст/обновлено, действие;
- пустое состояние без декоративной панели.

Для `/admin/release`:
- компактная release row/panel;
- версия, окружение, дата сборки при наличии, ссылки на desktop/runtime;
- без отдельного hero.

Для `/admin/system/status`:
- health table;
- реальные проверки отделить от статических утверждений;
- каждый check должен иметь статус, источник и действие при ошибке.

### Right inspector

Назначение:
- контекст текущей вкладки;
- system/release/runtime состояние;
- быстрые переходы;
- подсказки по выбранной строке.

Для обзора:
- status center;
- release/runtime;
- summary API status;
- выбранный риск или выбранная операционная зона;
- короткие CTA: открыть приемку, публикацию, склад, desktop tool.

## Нужные правки

- Перестроить `DashboardWorkspace` под трехзонный layout.
- Убрать тяжелый общий hero-header из режимов.
- Свести KPI к компактным chips/rows.
- Заменить крупные карточки `/admin` на очередь внимания.
- Перенести release/status/runtime в right inspector, оставить отдельные маршруты как детальные панели.
- Для `/admin/operations` сделать workbench с операционными группами, а не карточную карту.
- Для `/admin/risks` сделать сортируемый список блокеров.
- Разделить реальные health checks и статические справочные статусы.
- Добавить единый empty/loading/error pattern для всех режимов.
- Сохранить текущие маршруты и обратную совместимость `/admin?view=...`.

## Ожидаемое состояние после редизайна

- `/admin` открывается как рабочая сводка, а не витрина KPI.
- `/admin/operations` показывает, где сейчас есть работа.
- `/admin/risks` показывает приоритетные блокеры и действия.
- `/admin/release` становится компактным техническим экраном.
- `/admin/system/status` не дублирует системную навигацию, а дает проверяемый health view.
- Правая панель стабильно содержит контекст, статус и быстрые действия.
