# Вкладка: Telegram

## Что есть сейчас

Routes: `/admin/telegram`, `/admin/telegram/recipients`, `/admin/telegram/events`, `/admin/telegram/chats`, `/admin/telegram/test`.

`TelegramBots.tsx` уже содержит отдельный Telegram workspace:

- режимы: `Боты`, `Получатели`, `События`, `Чаты`, `Тест`;
- список ботов отображается горизонтальными tabs;
- есть создание, обновление, удаление бота;
- есть dirty-state и предупреждение при уходе с несохраненными изменениями;
- token редактируется и проверяется через validate action;
- username появляется после проверки token;
- получатели настраиваются через role toggles, ручные `chat_id`, low-stock threshold;
- события настраиваются группами с массовыми действиями `Все` и `Сброс`;
- recent chats загружаются для активного бота;
- `chat_id` можно копировать;
- сохранение/отмена/удаление вынесены в sticky bottom bar.

## UX/UI проблемы

- Внутренние режимы есть, но они живут как горизонтальные tabs и отдельные full-width секции.
- Активный бот выбран через горизонтальный tab bar, а не через левый список.
- Нет постоянного right inspector с health/status выбранного бота.
- Token/test выглядит как обычная форма, хотя это secret/config зона.
- Sticky bottom bar дублирует роль inspector и закрывает нижнюю часть workspace.
- События занимают весь центр, но не дают быстрый summary по выбранному боту справа.
- Получатели, события и чаты не имеют единого контекстного inspector.
- Recent chats используются как список, но выбранный чат не раскрывается справа.
- Удаление бота находится в общей sticky action bar, его нужно отделить как danger action.
- Много английских технических слов: `Telegram center`, `token`, `low-stock`, `Recent chats` в рабочем интерфейсе.

## Как должно выглядеть

Three-zone модель для раздела `Система`.

- **Left rail:** список ботов, локальные режимы Telegram, dirty indicators, кнопка создания.
- **Center workbench:** текущий режим выбранного бота: token config, получатели, матрица событий, чаты, тест.
- **Right inspector:** статус выбранного бота, token health, username, несохраненные изменения, save/reset/test, danger zone.

Telegram должен быть системной конфигурацией, а не отдельным набором страниц.

## Ожидаемое состояние

- Left rail содержит список ботов и локальные режимы `Боты`, `Получатели`, `События`, `Чаты`, `Тест`.
- Center меняется по выбранному режиму, но не меняет общий каркас страницы.
- Right inspector всегда показывает выбранного бота и состояние сохранения.
- Проверка token, сохранение и сброс доступны в inspector.
- Удаление бота находится только в inspector danger zone.
- В режиме `Получатели` inspector показывает итог: роли, manual recipients count, low-stock threshold.
- В режиме `События` inspector показывает количество включенных событий и проблемные группы.
- В режиме `Чаты` center показывает список, inspector показывает выбранный чат и copy actions.
- В режиме `Тест` center содержит форму тестового уведомления, inspector показывает результат отправки.
- Secret/token зона визуально отделена от повседневных переключателей.

## Нужные правки

- Перенести список ботов из горизонтальных tabs в left rail.
- Перенести локальные режимы Telegram в left rail или компактный segmented control внутри left rail.
- Заменить sticky bottom bar на right inspector actions.
- Добавить selected chat/recipient/event context для inspector.
- Сгруппировать token/test как protected config.
- Перенести delete в danger zone inspector.
- Привести тексты к русскому рабочему языку.
- Сохранить текущую dirty-state защиту при смене бота, обновлении и уходе со страницы.
- Сохранить существующие API-контракты `/api/telegram/bots*`.

## Быстрые действия

- Проверить token.
- Сохранить настройки.
- Сбросить несохраненные изменения.
- Скопировать chat ID.
- Отправить тестовое уведомление.
- Удалить бота через danger zone.
