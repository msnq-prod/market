# План переработки Video Tool (Бэклог и архитектурный инвентарь)

Этот документ описывает текущую архитектуру, состояние и план рефакторинга/переработки Video Tool для репозитория `stones`.

## 1. Текущий жизненный цикл (Workflow)

```mermaid
graph TD
    A[Импорт Source] --> B[Создание Черновика (Draft)]
    B --> C[Нарезка сегментов (Segments)]
    C --> D[Генерация манифеста (Manifest)]
    D --> E[Создание сессии экспорта (Session)]
    E --> F[Рендеринг роликов (Render)]
    F --> G[Загрузка артефактов (Upload)]
    G --> H[Обновление item_video_url]
```

Подробное описание этапов:
1. **Source Import**: Оператор перетаскивает или выбирает файлы исходных видео.
2. **Draft**: Накапливается черновик монтажа во временном состоянии (хранится в localStorage или в Electron `userData` в виде JSON).
3. **Segments**: Границы стыков, переходов и вырезанных фрагментов (gaps).
4. **Manifest**: Описание исходных файлов, результирующих сегментов и того, как каждый из них сопоставляется с товаром (`item_id` и `serial_number`).
5. **Session**: На бэкенде создается запись `BatchVideoExportSession` в статусе `OPEN`, фиксирующая манифест рендеринга и ожидаемое количество файлов.
6. **Render**: Локальный или встроенный `Video Helper` на базе ffmpeg выполняет склейку и нарезку по манифесту.
7. **Upload**: Отдельные ролики загружаются на бэкенд поштучно (сначала `intro.mp4`, затем ролики для товаров).
8. **Item Video URL**: Бэкенд обновляет `item_video_url` у соответствующих `Item` только после успешного завершения сессии (когда загружены все ожидаемые файлы).

## 2. Карта состояний (States Inventory)

В процессе монтажа и экспорта задействованы следующие группы состояний:

| Компонент / Слой | Название состояния | Описание / Где хранится |
| :--- | :--- | :--- |
| **Helper State** | Статус локального хелпера | `checking`, `ready`, `unavailable`, `version_mismatch` (хранится в UI и проверяется через `/health`). |
| **Source State** | Список исходных файлов | Метаданные (размер, хеш, длительность, статус привязки локального файла) в `WorkingSource[]`. |
| **Draft State** | Черновик сессии монтажа | Сегменты, привязанные исходники, ID сессии. Сохраняется в localStorage или через IPC в `userData`. |
| **Export Session** | Статус бэкенд-сессии | `OPEN`, `UPLOADING`, `COMPLETED`, `FAILED`, `CANCELLED`, `ABANDONED` (в БД, сущность `BatchVideoExportSession`). |
| **Workflow State** | Фоновый процесс Electron | Отслеживание этапов рендеринга и загрузки в Electron Main Process (`MediaWorkflowManager`). |
| **Upload Queue** | Очередь загрузки файлов | Состояние пачки загрузок `MediaUploadQueue` с индикацией прогресса. |
| **Network State** | Доступность бэкенда | Сетевой статус (`online` / `offline`) для приостановки/возобновления операций. |

## 3. Таблица ошибок (Error Matrix)

| Ошибка | Причина | Поведение сейчас | Требуемое поведение (v2) |
| :--- | :--- | :--- | :--- |
| **Нет helper** | Хелпер не запущен / заблокирован браузером | UI показывает предупреждение, экспорт заблокирован. | Улучшенный Preflight; понятная пошаговая диагностика и сбор логов. |
| **Нет сети** | Пропал интернет во время выгрузки | Фоновый workflow пытается делать ретраи, в UI статус виснет. | Переход workflow в явное состояние `paused_offline` с авто-возобновлением при коннекте. |
| **Auth expired** | Истекло время жизни JWT токена | Загрузка падает с 401/403, workflow переходит в `failed`. | Приостановка workflow в состояние `auth_required`, возобновление после логина. |
| **Мало места** | Недостаточно диска на машине оператора | Падает рендеринг ffmpeg посередине процесса. | Проверка свободного места на этапе Preflight перед запуском рендеринга. |
| **Corrupt video** | Поврежден исходный файл | Падает ffprobe/ffmpeg при анализе или рендере. | Preflight-декодирование короткого фрагмента, проверка кодеков и структуры. |
| **Partial upload** | Не все файлы залились из пачки | Сессия остается в статусе `UPLOADING` или `ABANDONED` по таймауту. | Возможность `per-item retry` загрузки отдельного файла без перезапуска всей партии. |
| **Cancelled session** | Отмена сессии оператором | Статус `CANCELLED`, прерывание фоновых задач в Helper и Main. | Корректный останов процессов ffmpeg, очистка кэша и пересоздание новой сессии. |
| **Stale session** | Сессия зависла (оператор закрыл вкладку) | Становится `ABANDONED` через 15 минут неактивности. | Electron Main продолжает фоновый workflow независимо от состояния вкладки/окна. |

## 4. Документация текущих API (v1)

Все роуты монтируются в Express приложении под префиксом `/api/batches/:id`:

### 1. `GET /video-tool`
* **Назначение**: Получение информации для инициализации монтажного стола (список товаров партии, текущие статусы видеопроцессинга и экспорта).
* **Ответ**:
  ```json
  {
    "batch": {
      "id": "uuid",
      "status": "RECEIVED",
      "expected_output_count": 5,
      "video_export": { "session_id": "uuid", "status": "OPEN", "version": 1 }
    },
    "product": { ... },
    "items": [
      { "id": "uuid", "serial_number": "SN001", "item_video_url": null }
    ]
  }
  ```

### 2. `POST /video-export-sessions`
* **Назначение**: Создание новой сессии экспорта или возобновление совместимой существующей.
* **Тело запроса**:
  ```json
  {
    "expected_count": 5,
    "crossfade_ms": 200,
    "source_fingerprint": { "name": "source.mp4", "size": 12345 },
    "render_manifest": { "segments": [], "outputs": [] }
  }
  ```
* **Ответ**: Сериализованная сессия `session` и флаг `resumed` (true/false).

### 3. `GET /video-export-sessions/:sessionId`
* **Назначение**: Запрос детального статуса конкретной сессии (включая списки уже загруженных файлов).

### 4. `POST /video-export-sessions/:sessionId/intro-file`
* **Назначение**: Загрузка обработанного интро-файла (`intro.mp4`). Принимает `multipart/form-data`.

### 5. `POST /video-export-sessions/:sessionId/files`
* **Назначение**: Загрузка результирующего видеоролика для конкретного товара. Принимает `multipart/form-data` с полями `serial_number`, `checksum_sha256` и `file`.

### 6. `POST /video-export-sessions/:sessionId/retry-tail`
* **Назначение**: Сброс ошибок сессии и возврат списка `pending_serials`, которые еще нужно загрузить для успешного завершения.

### 7. `POST /video-export-sessions/:sessionId/cancel`
* **Назначение**: Принудительная отмена сессии оператором. Статус сессии меняется на `CANCELLED`.
